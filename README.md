# lead-button

Отдельная веб-страница «Получить лид»: менеджер заходит по ссылке, входит
своим логином AmoCRM (OAuth — пароль видит только AmoCRM, не мы), жмёт
кнопку — ему назначается следующий подходящий лид по правилам (группа
менеджера ↔ тег лида, лимит выдач в месяц). Вся конфигурация и состояние
(группы, лимиты, счётчики, воронка-источник/назначение) хранятся в самом
AmoCRM через «Списки» (Catalogs API v4) — без внешней БД.

Не виджет AmoCRM — обычная страница, достаточно «Внешней интеграции»
AmoCRM (доступ по API + OAuth), без загрузки кастомного JS-кода в аккаунт.
Два уровня доступа: менеджеры входят через OAuth AmoCRM и видят только
кнопку и сколько лидов доступно (сервер узнаёт, кто перед ним, из самого
входа — выбрать чужую фамилию нельзя); настройки (`/settings`) — отдельный
Basic Auth логин для владельца/руководителей.

Это отдельный, самостоятельный проект — не связан с другими вашими
репозиториями/дашбордами, свой сервис на Render, свой git-репозиторий.

## Локальный запуск

```bash
pip3 install -r requirements.txt
cp .env.example .env   # если .env ещё нет — заполнить значения (см. ниже)
python3 app.py
```

Слушает `http://127.0.0.1:5060`.

## Переменные окружения

См. `.env.example`. Коротко:
- `AMOCRM_SUBDOMAIN` / `AMOCRM_TOKEN` — сервисный доступ к API AmoCRM
  (долгосрочный токен, создаётся в Настройки → Интеграции → Внешняя
  интеграция) — используется бэкендом для чтения/записи сделок.
- `AMOCRM_OAUTH_CLIENT_ID` / `_SECRET` / `_REDIRECT_URI` — ОТДЕЛЬНАЯ
  интеграция (тоже «Внешняя», с указанным Redirect URI = `<адрес
  сервиса>/oauth/callback`) — только чтобы узнать, какой реальный
  пользователь AmoCRM сейчас входит на страницу `/`.
- `FLASK_SECRET_KEY` — подпись cookie сессии менеджера после входа.
- `LEAD_BUTTON_ADMIN_USER` / `LEAD_BUTTON_ADMIN_PASS` — логин настроек (`/settings`).
- `LEAD_BUTTON_*` — ID трёх списков AmoCRM («Распределение: группы»,
  «…счётчики», «…настройки») и их полей. Создаются один раз скриптом
  `_setup_lead_button.py` (идемпотентен — безопасно перезапускать).

Если списки ещё не созданы:
```bash
python3 _setup_lead_button.py
```
Скрипт создаст списки в вашем AmoCRM-аккаунте и выведет готовый блок для
`.env`.

## Деплой на Render

1. На [render.com](https://render.com) → New → Web Service → подключить этот
   репозиторий на GitHub.
2. Render подхватит `render.yaml` (Blueprint) — подтвердить создание сервиса
   с именем `lead-button` (или другое, если занято).
3. В настройках сервиса на Render заполнить все переменные окружения из
   `.env.example` реальными значениями (они помечены `sync: false` в
   `render.yaml`, то есть не подтягиваются автоматически — вписать руками).

## Использование

- `/` — страница «Получить лид» для менеджеров.
- `/settings` — настройки: группы менеджеров, теги, лимиты, воронка-источник
  и назначение. Открывать администратору.

Ссылку на `/` можно закрепить у себя в браузере/панели задач — заменяет
кнопку внутри AmoCRM.

## Структура

```
app.py                  — Flask: страницы + /api/get-lead, /api/settings
amocrm.py                — тонкий клиент AmoCRM API v4 (только то, что нужно кнопке)
lead_distribution.py     — бизнес-логика распределения лидов
_setup_lead_button.py    — разовый скрипт создания списков в AmoCRM
templates/                — index.html (кнопка), settings.html (настройки)
static/app.js             — вся клиентская логика обеих страниц
render.yaml               — конфигурация деплоя на Render
```
